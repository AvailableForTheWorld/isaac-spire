# 成就、秘密与道具解锁系统

## 设计目标

成就系统同时承担三件事：记录玩家长期经历、给一次精彩操作即时反馈、分批开放 718 件道具以控制新手期的信息密度。它不是写在战斗流程里的零散 `if`，而是一个只依赖领域事件的独立模块。

首批 36 项成就参考了《The Binding of Isaac: Rebirth》的首领推进、商店累计升级、无伤层和秘密解锁思路，也采用了《Slay the Spire》的 Minimalist、Common Sense、Speed Climber、Impervious、Adrenaline 等挑战型目标。参考来源：[Isaac Steam 成就列表](https://steamcommunity.com/stats/250900/achievements)、[Isaac 游戏推进说明](https://bindingofisaacrebirth.wiki.gg/wiki/Game_Progression)、[Slay the Spire Steam 成就列表](https://steamcommunity.com/stats/646570/achievements)。数值、牌组规模和奖励均按照本项目的回合制网格规则重新平衡，并非照搬原作。

## 领域结构

```text
游戏命令
  └─ 发布 AchievementEvent（击杀、消费、献祭、通关……）
       └─ recordAchievementEvent：唯一的计数归约器
            ├─ lifetimeCounters：跨局累计/历史峰值
            ├─ runCounters：本局计数/结算快照
            └─ changedMetrics
                 └─ ACHIEVEMENTS_BY_METRIC 反向索引
                      └─ 条件规格求值
                           ├─ 解锁道具
                           ├─ 生成前端通知
                           └─ 进入 Steam 待同步集合
```

采用的模式：

- **事件驱动**：战斗、商店和 UI 不知道成就阈值，只发布带枚举类型的事实。
- **规格模式**：一个成就是若干 `AchievementRequirement` 的合取；要求由指标、作用域、比较方式和目标值组成。
- **策略/端口适配器**：`AchievementPlatformPort` 隔离 Steamworks。领域层只产出稳定平台键，不依赖 Steam SDK。
- **反向索引**：启动时把 `AchievementMetric -> AchievementDefinition[]` 建成 `Map`。一次事件只检查受影响的成就，而非每次扫描整个目录。
- **幂等差异同步**：完成集合和平台已同步集合都以稳定 ID 存储。`pendingPlatformUnlocks` 只返回差集，Steam 回调成功后才调用 `markPlatformAchievementsSynced`。
- **声明式内容目录**：新增成就主要是添加一条数据定义；只有新的事实类型才需要扩展事件归约器。

所有持久化判别值都来自 `domain/enums.ts`。成就 ID 和 `steamKey` 一经发布就是存档/API 数据，不能直接改名；必须改名时应增加迁移和 Steam 后台兼容映射。

## 指标与作用域

`Lifetime` 指标跨局保存，包括击杀数量、消费、献祭生命、打牌数以及金币/护盾/体力历史峰值。`Run` 指标在开局时清空，包括本局天使好感、最终牌组大小、最终道具数、通关时间和单回合打牌数。

比较方式为 `AtLeast`、`AtMost`、`Equal`。例如“累计消费 200”使用 Lifetime + AtLeast；“最终牌组不超过 12 张”使用 Run + AtMost，并与本局获胜条件组合。

当前领域事件包括：敌人死亡、无伤精英、首领死亡、房间/楼层清理、消费、献祭、进入隐藏房、使用炸弹、打牌、新回合、天使好感、恶魔交易和本局获胜。所有计数均在命令成功、资源实际扣除后记录，失败或取消购买不会累计。

## 存档、一致性与迁移

档案只保存稳定 ID、完成时间、数值指标和平台同步 ID，不复制成就定义，因此增加文案或调整展示不会让存档膨胀。运行快照额外保存临时 `runCounters` 和本局通知。

每条本局通知带有可选的 `acknowledgedAt`。未确认通知会先嵌入房间宝箱奖励画面，确认宝箱后进入持久提示队列；它不会按计时器消失，存档或恢复游戏后仍会出现，直到玩家明确点击确认。通知确认不影响成就完成状态和 Steam 待同步状态。

`mergeAchievementProgress` 使用集合并集、完成时间最早值和计数器最大值合并。原因是客户端快照已经从档案基线开始累计；服务器可能因自动保存重试收到同一快照，用相加会重复记账，用最大值则保持幂等。当前产品只有一个活动局。未来允许多设备并发独立局时，应给局分配事件序列/增量账本，在服务器按 `(runId, eventId)` 去重后相加，而不是继续依赖最大值。

旧档案通过纯函数迁移补上空的 `achievementProgress`；旧运行补上 `achievementState` 和通知数组。迁移可以重复执行且不改变已有进度。

## Steam 接入步骤

1. 在 Steamworks 后台以 `steamKey`（例如 `ACH_MOM_LEG`）创建对应成就；键值必须与代码一致。
2. 在桌面客户端/Steam 壳层实现 `AchievementPlatformPort.unlock(entries)`，内部调用 Steamworks `SetAchievement` 和 `StoreStats`。
3. 载入档案后调用 `pendingPlatformUnlocks(profile, AchievementPlatform.Steam)`。这也能把接入 Steam 前已完成的本地成就补发到 Steam。
4. 仅在 `StoreStats` 成功回调后调用 `markPlatformAchievementsSynced` 并保存档案。离线或失败时保留待同步差集，下次重试。
5. Steam 回调只能确认平台同步，不能反向决定游戏内道具解锁；本地域始终是玩法进度的权威来源。

这样 Steam SDK 不会进入浏览器、NestJS 或纯游戏包，也不会让离线游戏因平台故障丢失解锁。

## 新增成就清单

1. 在 `AchievementId`、必要的 `AchievementMetric` / `AchievementEventType` 中增加稳定枚举值。
2. 在 `domain/achievement.ts` 扩展类型化事件载荷，避免 `Record<string, unknown>`。
3. 在命令成功点发布事件，并在 `recordAchievementEvent` 中归约为一个或多个指标。
4. 在 `achievements/catalog.ts` 添加声明式定义，给出中英文、类别、等级、条件和奖励道具 ID。
5. 给事件接线、阈值、重复存档和旧档迁移补测试。
6. 在 Steamworks 后台创建同名平台键；不要复用或改写已经上线的键。

成就目录测试会检查 ID、Steam 键唯一性、奖励道具存在性，并保证成就奖励不会误入新档案初始解锁池。
